# ЛР №3 — вариант 18. Запуск в Linux

Две программы: **C++** находится в `lab3/`, **Rust** — в `lab3_rust/`.
Это обычные консольные проекты Linux. Сборка C++ рассчитана на **g++ / GNU Make / CMake**, Rust — на **cargo**.
Windows, Visual Studio и `.exe` не нужны.

## 1. Что установить

Пример для **Ubuntu / Debian** (команды `sudo apt` приведены только для этих дистрибутивов):

```bash
sudo apt update
sudo apt install build-essential cmake python3 clang-tidy gcovr
```

Для полного набора C++-тестов понадобятся **Google Test, Boost.Test, Catch2 версии 3**.
Чаще всего Google Test и Boost.Test можно установить командами:

```bash
sudo apt install libgtest-dev libboost-test-dev
```

Проверьте доступную версию `catch2` в репозитории вашего Linux.
Если там **Catch2 v2**, она не подойдёт: в данном проекте используются заголовки Catch2 **v3**.
Нужно установить Catch2 v3, иначе CMake сообщит об отсутствующей зависимости.

Для Rust установите компилятор Rust и Cargo с официального сайта **rustup.rs**,
затем в терминале:

```bash
rustup component add clippy llvm-tools-preview
```

Для HTML-отчёта Rust дополнительно нужен `cargo-llvm-cov`:

```bash
cargo install cargo-llvm-cov
```

## 2. Запуск программы C++

Откройте терминал в папке `lab3`:

```bash
cd lab3
make
./dbms --file demo.bin --query 'MPUSH arr "hello world"'
./dbms --file demo.bin --query 'MGET arr 0'
```

В ответ на последнюю команду будет `hello world`. На Linux исполняемые файлы
запускаются с `./` — например, `./dbms`, `./benchmark_cpp`.

**Сохранение:** файл `demo.bin` — двоичный. Файл `demo.data` — прежний текстовый.
Текстовые данные остаются совместимыми с Rust, но в исходном текстовом формате
пробелы внутри значения поддерживаются не полностью. Для строк с пробелами в C++
используйте `.bin`.

### Как устроен `.bin`

Запись происходит в `binary_storage.cpp`:

1. `write_binary_records()` открывает файл в бинарном режиме и записывает заголовок `LB3B`, версию `1` и число структур.
2. Затем для каждой структуры пишет её **тип, имя и значения**.
3. Перед каждой строкой пишет её длину (4 байта), поэтому строка может содержать пробелы.
4. `read_binary_records()` читает те же данные в обратном порядке, проверяя формат и размеры.

Формат **не изменён** по сравнению с предыдущим исправленным архивом: версия 1, числа из 4 байт (little-endian). Файлы `.bin` старой исправленной версии сохраняют совместимость. Максимальная длина одной строки — 1 МБ. Эта реализация относится к C++; Rust пока использует свой текстовый формат.

## 3. Бенчмарки — измерение скорости

В `lab3/bench/benchmark.cpp` и `lab3_rust/src/bin/benchmark.rs` теперь используются
**простые функции, циклы и измерение времени**. Нет шаблонов, лямбда-функций и FnMut.

Принцип каждого измерения:

1. Создаём пустую структуру и запоминаем время начала.
2. Добавляем `N` элементов, запоминаем время конца.
3. Если у структуры есть поиск, измеряем его **после** заполнения.
4. Повторяем три раза, выводим среднее время **одной операции в наносекундах**.

```bash
cd lab3
make benchmark
./benchmark_cpp 5000
./benchmark_cpp 2000 > results_cpp.csv
```

Для Rust:

```bash
cd lab3_rust
cargo run --release --bin benchmark -- 2000
cargo run --release --bin benchmark -- 2000 > results_rust.csv
```

CSV содержит столбцы `structure,operation,elements,mean_ns_per_operation`.
Меньшее время — быстрее. **Числа зависят от Linux-компьютера**. Большие `N`
могут работать очень долго при линейном поиске по спискам. Rust-бенчмарк
запускайте с `--release`, иначе сравнение будет некорректным.
Поскольку реализации могут по-разному копировать строки, сравнивайте прежде
всего разные операции **внутри одной версии**, а не языки между собой.

## 4. Линтеры

```bash
cd lab3
make lint             # clang-tidy проверит *.cpp и бенчмарк
```

Настройки C++ лежат в `.clang-tidy`, скрипт запуска — `scripts/lint_cpp.sh`.

```bash
cd lab3_rust
make lint             # cargo clippy --all-targets -- -D warnings
```

Линтер **не запускает** приложение; он указывает на подозрительные места в коде.
Предупреждения в старом исходном коде тоже могут появляться — их нужно разбирать.

## 5. Как работают тесты

**C++:**

- `tests/test_array.cpp`, `test_stack.cpp`, `test_queue.cpp` — Catch2 v3.
- `tests/test_ulist.cpp`, `test_dlist.cpp` — Google Test.
- `tests/test_avltree.cpp`, `test_hashtable.cpp` — Boost.Test.
- `tests/test_safety.cpp` — отдельные проверки опасного копирования и размера массива.
- `tests/test_cli.py` — запускает `dbms`, отправляет реальные команды и проверяет сохранение/загрузку данных (включая повреждённые файлы).

**Быстрый тест**, не требующий библиотек Google Test, Boost.Test и Catch2:

```bash
cd lab3
make test-cli
```

**Полный прогон** (требуются все три фреймворка):

```bash
cd lab3
make test
```

Это запускает CMake и `ctest`: он выполняет все тестовые программы. В одной
программе находятся **многие отдельные тесты**, поэтому число записей CTest
меньше числа проверок `TEST_CASE`, `TEST` и `BOOST_AUTO_TEST_CASE`.

**Покрытие тестами** измеряет, какая доля строк кода выполнилась при тестировании.

```bash
cd lab3
make coverage
```

`gcovr` создаст HTML-файл `lab3/build-coverage/coverage/index.html` и проверит
порог **85%** для реализаций структур данных C++. Наличие команды не гарантирует
85%: если тестов недостаточно, команда завершится ошибкой.

**Rust:** тесты находятся в модулях `#[cfg(test)]` внутри `src/*.rs`:

```bash
cd lab3_rust
cargo test
make coverage
```

Покрытие Rust требует установленного `cargo-llvm-cov`; HTML: `target/llvm-cov/html/index.html`.
