# Архитектура TaskManager

## 1. Назначение программы

TaskManager - консольная программа на C++ для управления заданиями. Пользователь может создать задание, найти его по ID, посмотреть список, запустить следующее задание, завершить или отменить его, а также получить статистику.

Основная логика находится в классе TaskManager. Он объединяет три самостоятельно реализованные структуры данных: динамический массив Arr, хеш-таблицу HashTable и бинарную кучу Heap.

## 2. Модель задания

Каждое задание представлено структурой **Task** из файла src/tasks.h.

| Поле       | Тип          | Назначение                             |
| ---------- | ------------ | -------------------------------------- |
| id         | uint64_t     | Уникальный идентификатор задания       |
| type       | string       | Тип задания                            |
| payload    | string       | Данные задания                         |
| priority   | unsigned int | Приоритет от 0 до 100                  |
| status     | string       | Текущее состояние                      |
| created_at | string       | Время создания                         |
| updated_at | string       | Время последнего изменения             |
| error      | string       | Текст ошибки при неуспешном завершении |

Новый ID выдаётся из счётчика next_id, начиная с 1. Счётчик next_order нужен для сохранения порядка создания в приоритетной очереди. Время записывается в формате YYYY-MM-DD HH:MM:SS.

## 3. Используемые структуры данных

### 3.1. Динамический массив Arr

Файлы: src/dinarray.h, src/dinarray.cpp.

Массив является основным хранилищем заданий. В нём находятся полные объекты **Task**. При заполнении выделенного места вместимость увеличивается в два раза, а элементы копируются в новый массив.

Задания добавляются в конец. Поэтому при просмотре списка они выводятся в порядке создания. При обращении по известному индексу можно сразу получить нужное задание.

### 3.2. Хеш-таблица HashTable

Файлы: src/table.h, src/table.cpp.

Хеш-таблица ускоряет поиск задания по ID. В её узлах хранятся id и индекс задания в Arr, а не копия всего задания.

Для вычисления хеша используется смешивание битов по алгоритму, близкому к **splitmix64**. Номер ячейки вычисляется как **hash(id) % capacity**.

**Разрешение коллизий:** метод цепочек. Если разные ID попадают в одну ячейку, узлы связываются указателями next в односвязный список. При поиске программа проходит по этой цепочке и сравнивает ID.

**Изменение размера:** после вставки вычисляется коэффициент заполнения size / capacity. Когда он достигает **0.75** или превышает его, вместимость таблицы удваивается. Узлы перераспределяются по новым ячейкам с учётом новой вместимости. Также считаются количество расширений и максимальный коэффициент заполнения.

### 3.3. Бинарная куча Heap

Файлы: src/heap.h, src/heap.cpp.

Куча используется как очередь заданий. Каждый её элемент HeapNode содержит только id, priority и order.

Сначала выбирается задание с большим приоритетом. Если приоритеты равны, раньше выбирается задание с меньшим order, то есть созданное раньше.

Куча хранится во внутреннем динамическом массиве. При добавлении выполняется siftUp, при извлечении - siftDown. Если массив заполнен, его вместимость удваивается.

## 4. Как структуры работают вместе

В классе TaskManager используются три поля:

```cpp
Arr tasks;
HashTable table;
Heap heap;
```

При создании задания:

1. Формируется новый объект Task со статусом queued.
2. Задание добавляется в Arr.
3. В HashTable добавляется пара id -> индекс в массиве.
4. В Heap добавляется элемент с ID, приоритетом и порядком создания.
5. Счётчики next_id и next_order увеличиваются.

При поиске по ID хеш-таблица возвращает индекс, по которому задание берётся из массива. При запуске следующего задания куча возвращает ID наиболее приоритетного элемента, а само задание находится через хеш-таблицу.

Таким образом, массив отвечает за хранение данных, хеш-таблица - за быстрый поиск, а куча - за выбор следующего задания.

## 5. Состояния и переходы

completed, failed и cancelled - конечные состояния. Изменения состояния вне указанных переходов не допускаются. Например, нельзя завершить задание, которое ещё не было запущено, или отменить уже выполняющееся задание. В таких случаях метод выбрасывает исключение.

Вызов fail сохраняет описание ошибки в поле error. При изменении состояния обновляется updated_at.

Если в куче нет подходящих заданий, startNextTask() выбрасывает out_of_range с сообщением «Нет задач для запуска».

## 6. Согласованность массива, индекса и очереди

У каждого задания есть одна основная запись в Arr. HashTable хранит ссылку на эту запись в виде индекса, а Heap хранит информацию для выбора задания по приоритету.

При создании задания обновляются все три структуры. Если добавление завершается ошибкой, createTask() пытается откатить изменения в массиве и хеш-таблице.

При отмене задания его статус в Arr меняется на cancelled, но элемент может физически остаться в куче. Используется **ленивое удаление**: метод startNextTask() проверяет статус найденного задания и пропускает элементы, которые уже не находятся в состоянии queued.

При запуске подходящий элемент удаляется из кучи, а статус задачи меняется на running. Завершённые, отменённые и запущенные задания остаются в массиве и хеш-таблице.

## 7. Сохранение и загрузка данных

Программа принимает путь к файлу через параметр --data. Формат хранения выбирается по расширению:

| Расширение | Формат           |
| ---------- | ---------------- |
| .dat, .txt | Текстовый формат |
| .json      | JSON             |

### 7.1. Текстовый формат

Текстовый файл начинается с маркера TASKS_TXT. Затем записываются next_id, next_order, число заданий и их поля. Строковые значения сохраняются с помощью quoted.

Пример начала файла:

```text
TASKS_TXT
2 1
1
```

Здесь следующий ID равен 2, следующий порядковый номер - 1, в файле одно задание. После заголовка идут строки с данными заданий.

### 7.2. JSON-формат

Для работы с JSON используется библиотека nlohmann/json. В корневом объекте записаны обозначение формата, счётчики и массив задач.

Пример структуры:

```json
{
    "next_id": 2,
    "next_order": 1,
    "tasks": [
        {
            "id": 1,
            "type": "test",
            "payload": "hello",
            "priority": 80,
            "status": "queued",
            "created_at": "2026-11-25 12:00:00",
            "updated_at": "2026-11-25 12:00:00",
            "error": ""
        }
    ]
    "version": "TASKS_JSON"
}
```

### 7.3. Защита данных при загрузке и записи

Если файл отсутствует, TaskManager начинает работу с пустого состояния. Если файл существует, выполняется чтение и проверка данных: формата, полей, статусов, приоритетов, ID и счётчиков.

Задания сначала загружаются во временный объект TaskManager loaded. Для каждой задачи восстанавливаются массив и хеш-индекс. В кучу возвращаются только задания со статусом queued. После успешной загрузки состояние заменяется с помощью swap(loaded). Если проверка не прошла, прежнее состояние менеджера не заменяется.

При сохранении сначала создаётся временный файл с расширением .tmp, после успешной записи и закрытия он переименовывается в основной файл. Это позволяет не перезаписывать основной файл напрямую при ошибке записи.
