# TaskManager

Консольная программа на C++ для хранения задач и управления их выполнением. Программа позволяет создавать задачи, искать их по ID, выбирать следующую по приоритету, изменять статус и сохранять состояние между запусками.

Для хранения и обработки задач используются собственные структуры данных: динамический массив (`Arr`), хеш-таблица (`HashTable`) и бинарная куча (`Heap`).

## Требования

- C++17 и компилятор с поддержкой этого стандарта;
- CMake версии 3.16 или новее;
- доступ к интернету при первой настройке CMake для загрузки GoogleTest и nlohmann/json.

## Сборка

Откройте терминал в папке **sub** и выполните:

```bash
cmake -S . -B build
cmake --build build
```

После сборки появятся исполняемые файлы build/taskctl и build/benchmark, а также программы тестирования.

## Запуск

Общий вид команды:

```bash
./build/taskctl --data <путь_к_файлу> <команда> [аргументы] [--format text|json]
```

Параметр `--data` задаёт файл, в котором сохраняются задачи. Если файл ещё не существует, программа начинает с пустого состояния. Файл создаётся после первой успешной операции, изменяющей данные.

Для получения списка команд:

```bash
./build/taskctl --data tasks.dat help
```

## Команды

| Команда                                                    | Назначение                               |
| ---------------------------------------------------------- | ---------------------------------------- |
| `create --type <тип> --priority <число> --payload <текст>` | Создать задачу                           |
| `get <id>`                                                 | Получить задачу по ID                    |
| `list`                                                     | Показать все задачи                      |
| `list --status <статус>`                                   | Показать задачи с выбранным статусом     |
| `start-next`                                               | Запустить следующую ожидающую задачу     |
| `complete <id>`                                            | Успешно завершить выполняющуюся задачу   |
| `fail <id> --error <текст>`                                | Завершить выполняющуюся задачу с ошибкой |
| `cancel <id>`                                              | Отменить ожидающую задачу                |
| `stats`                                                    | Показать статистику                      |
| `help`                                                     | Показать доступные команды               |

Приоритет задаётся целым числом от **0 до 100**. Чем больше число, тем выше приоритет. При одинаковом приоритете раньше запускается задача, созданная раньше.

Возможные статусы: queued, running, completed, failed, cancelled.

Команда list выводит задачи в порядке создания (по возрастанию ID).

## Пример работы

Создание двух задач:

```bash
./build/taskctl --data tasks.json create --type calc --priority 80 --payload "2 + 2"
./build/taskctl --data tasks.json create --type backup --priority 30 --payload "Copy"
```

Просмотр задач и получение информации по ID:

```bash
./build/taskctl --data tasks.json list
./build/taskctl --data tasks.json get 1
./build/taskctl --data tasks.json list --status queued
```

Запуск задачи с наибольшим приоритетом и её завершение:

```bash
./build/taskctl --data tasks.json start-next
./build/taskctl --data tasks.json complete 1
```

Запуск следующей задачи и завершение с ошибкой:

```bash
./build/taskctl --data tasks.json start-next
./build/taskctl --data tasks.json fail 2 --error "File not found"
```

Просмотр статистики:

```bash
./build/taskctl --data tasks.json stats
```

Пример отмены новой ожидающей задачи:

```bash
./build/taskctl --data tasks.json create --type mail --priority 50 --payload "Send report"
./build/taskctl --data tasks.json cancel 3
```

## Форматы хранения данных

Формат определяется расширением файла в параметре `--data`:

| Расширение | Формат хранения | Обозначение внутри файла |
| --- | --- | --- |
| `.dat`, `.txt` | Текстовый | `TASKS_TXT` |
| `.json` | JSON | `TASKS_JSON` |

Примеры использования текстового и JSON-хранилища:

```bash
./build/taskctl --data tasks.dat create --type test --priority 10 --payload "Hello"
./build/taskctl --data tasks.json create --type test --priority 10 --payload "Hello"
```

При следующем запуске программа загружает состояние из указанного файла. После успешной команды, изменяющей задачи, состояние записывается заново. Сохранение выполняется сначала во временный файл (`.tmp`), затем он переименовывается в основной файл. Повреждённый файл вызывает ошибку и не перезаписывается автоматически.

Файлы разных форматов являются отдельными хранилищами: `tasks.dat` и `tasks.json` не синхронизируются друг с другом.

## Обработка ошибок

При неверной команде, несуществующем ID, недопустимом переходе статуса или повреждённом файле программа выводит сообщение об ошибке и завершает работу с ненулевым кодом. При неуспешной операции сохранённый файл не изменяется.

Если ожидающих задач нет, команда start-next выдаёт сообщение `Нет задач для запуска` и завершается с ошибкой.

## Тестирование

После сборки запустите все тесты GoogleTest:

```bash
ctest --test-dir build --output-on-failure
```

Тесты проверяют динамический массив, хеш-таблицу, кучу, операции TaskManager, а также сохранение и загрузку данных.

## Анализ производительности

Запуск эксперимента:

```bash
./build/benchmark
```

Программа создаёт **100 000 задач** и измеряет время добавления, поиска по ID и последовательного извлечения. Дополнительно выводятся количество расширений хеш-таблицы, максимальный коэффициент заполнения и контрольные суммы.

Теоретическая сложность операций и результаты измерений описываются в `COMPLEXITY.md`.
